# Public content contract

**Date:** 2026-10-29. **Applies to:** the site, the blog, FAQs, `llms.txt`, the plugin README and the repository README.

Production is waitlist-only and teases the launch; staging is the working app. Copy may describe what launch includes, but never presents planned work as working today.

## Labels

| Status | Label | Use for |
|---|---|---|
| Works on staging today | none | Quotes, pay pages, deposits, deliveries, payouts by approval or rule, the Network connector, guest checkout, digital products on the seller page |
| In the current backlog | **Coming next** | The contextual agent (quote preparation, business answers, agent-assisted payouts), store management with the agent |
| Approved, later than the current backlog | **Coming soon** or **Planned** | Web SEO on seller pages, your own domain, export, the public seller API and webhooks, Enterprise custom offers, AI visibility for Network members |
| Cancelled | removed | Multi-store cart (M), Discord request threads as a sales channel (E), AG Studio |

## Rules

- One contextual agent, not separate intake, payout or copilot agents. Its permissions come from the seller's operating model.
- Agents never move money. The payer approves every checkout in PayPal; a person or the seller's rule approves every payout.
- The client-facing Network connector and the seller API are different things; do not merge them in copy.
- A planned run is not evidence that a feature is available. Check `PROGRESS.md` and `BACKLOG.md` before calling anything live.
- Payments run on the PayPal sandbox during the alpha. Say "test mode" or "alpha", never "prototype" or "hackathon".
- Seller names in examples are illustrations, and the footer says so.
