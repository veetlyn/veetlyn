## How a run works

1. **Design.** Brainstorm with Mouhamed (one question at a time, approaches with a recommendation, design sections approved one by one). Write the design in `platform/` with a date prefix, add it to the context index (`README.md`, Live documents), update **Now**. Mouhamed reviews the written design before planning.
2. **Plan.** Write the plan in `platform/plans/`: base commit, branch, worktree, test database, facts with file and line references, tasks with checkboxes, a final controller task (review, merge, walkthrough) naming the story IDs it walks, and an empty Outcome section. Put the plan link and that task in the run's row here (Plan, Stories) and in the run's section of `stories/09-agentic.md`.
3. **Build.** When the build starts, set the run's stories to `In progress (<run>)`. One branch and worktree per run (for A1: branch `a1-action-registry`, worktree `worktrees/a1-action-registry`), its own test database (`jendal_test_a1`; see Environment for the commands). One worker per task; the controller reviews each task and the whole branch. Checks per task: `npx vitest run <paths>`, `pnpm check-types`, `pnpm lint`. Conventional Commits ending with `Co-authored-by: factory-droid[bot] <138933559+factory-droid[bot]@users.noreply.github.com>`. Never push.
4. **Merge.** `git merge --no-ff` into main, `pnpm install`, `pnpm db:migrate:dev` (check the dev data before and after), restart the dev stack.
5. **Walkthrough.** Run the plan's stories from [`stories/`](stories/README.md) in the PayPal sandbox with a browser agent (Playwright, Chrome DevTools or Claude in Chrome): on staging (`staging.payleor.com`, `dash.staging.payleor.com`, `api.staging.payleor.com`, `*.staging.payleor.app`, deployed by hand from the branch) before the merge, and on production after it. Mouhamed does the [human] steps (paying in the PayPal popup, Payouts Web uploads, plugin connectors, Discord accounts). Fixes found go in a follow-up branch.
6. **Record.** Fill the plan's Outcome, set the design's status, update the stories' statuses (and add stories for new features), move finished backlog rows to [`archive/backlog-done.md`](archive/backlog-done.md) and add new findings to Open, update the run board, **Now** and the context index, and [`platform/2026-10-16-architecture.md`](platform/2026-10-16-architecture.md) when the run changed hosts, bindings, packages, money flows or surfaces. Remove the worktree, branch and test database. A run is not marked done on the board until its plan's Outcome is filled in; then move the plan and its evidence to `archive/platform/plans/` (see the README's "Keeping this index useful").

Spec and plan edits are committed on main (`docs(specs): …`), not on feature branches.

The agent tooling named in plans (writing-plans, subagent-driven-development, explorer and worker subagents, Playwright and Chrome DevTools for walkthroughs) are Droid skills and subagents. A person can follow the same steps by hand: the plan's tasks are self-contained.

- **Set up from scratch:**
  1. `pnpm install` in `worktrees/main` (Varlock generates the env accessors).
  2. Env values: the keys are listed in each `.env.schema` (`apps/server`, `apps/web`, `packages/db`, `packages/infra`); values come from Mouhamed or the dashboards (PayPal developer, Cloudflare, Discord developer portal, Resend, AgentMail). They go in ignored env files (`apps/server/.env`, `.env.test.local`). Never print or commit them.

Postgres: `docker run -d --name jendal-pg --restart unless-stopped -p 5432:5432 -e POSTGRES_PASSWORD=<choose> -v jendal-pg-data:/var/lib/postgresql/data postgres:17`, then `docker exec jendal-pg createdb -U postgres jendal-dev`. `DEV_DATABASE_URL` points at it; `pnpm db:migrate:dev` migrates it.
  4. Files: R2 is emulated by `alchemy dev` (`/cdn-cgi/local/r2/s3` on the api port); no MinIO is needed.
  5. Local hosts: `pnpm dev` serves the site on `localhost:3001` and the dashboard on `dash.localhost:3001` (`admin.localhost` redirects there). The dev tunnel is retired: its DNS records were removed at the H cutover (2026-10-20), so `payleor.com` hosts always reach the deployed Workers.
  6. Dev: `pnpm dev` from `worktrees/main`. Stop with Ctrl-C; if a port stays taken, find the leftover `workerd`, `vite` or `alchemy` process with `ss -ltnp` and stop it. After a merge that changes dependencies, the web app can load two copies of React (blank page, "Invalid hook call"): stop dev, delete `apps/web/node_modules/.vite`, restart, clear the browser cache.
