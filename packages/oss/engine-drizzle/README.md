# @opmodel/engine-drizzle

Drizzle storage helpers for the operating-model engine: claim-with-row-lock, reconcile and window-count queries over any table shaped like the engine's schedule items, outbox deliveries or member marks. The host passes its table name; every row is zod-decoded before it leaves the SQL boundary. MIT, no platform code.

## Install

```bash
npm install @opmodel/engine-drizzle drizzle-orm zod
```

## Quickstart

```typescript
import { claimDueScheduleRows, completeScheduleRows, reconcileScheduleRows } from "@opmodel/engine-drizzle";

// Arm the timers a plan wants and retire the ones it no longer needs (idempotent upserts).
await reconcileScheduleRows(db, "schedule_item", {
  teamId: "team_1",
  subjectId: "project_1",
  schedule: [{ kind: "request.expire", runAt: new Date("2026-10-03T00:00:00Z") }],
  cancel: ["request.remind"],
});

// Keep claim locks, database effects and completion in the same transaction.
await db.transaction(async (tx) => {
  const claimed = await claimDueScheduleRows(tx, "schedule_item", new Date(), 20);
  // Perform database effects using tx, then complete the claimed occurrences.
  await completeScheduleRows(tx, "schedule_item", claimed.map((row) => row.id), { status: "done" });
});
```

## What is included

- `reconcileScheduleRows` — arm/move/cancel active items against a partial unique index; history is kept.
- `claimDueScheduleRows` — transactional `FOR UPDATE SKIP LOCKED` claims.
- `claimDueDeliveryRows` — atomic five-minute delivery leases with a fresh token and recoverable expiry. Send outside the transaction and fence outcome writes by id, pending status and claim token. Preserve a stable provider idempotency key and message across retries.
- `completeScheduleRows`, `setSchedulePaused` — done/failed outcomes and dispute holds.
- `countMarksInWindow` — the strike rule's rolling-window count.
- `ScheduleStore` / `DeliveryStore` — the contracts an adapter implements.

## Table shape

The helpers address columns by name: `id, team_id, subject_id, kind, run_at, status, attempts, last_error, payload, completed_at` (schedule), `id, outbox_id, channel, recipient, attempts, status, next_attempt_at, claim_token, claim_expires_at, first_attempt_at` (deliveries) and `id, team_id, member_user_id, kind, created_at` (marks). Ids are generated by the caller's stack — inserts pass a UUID.
